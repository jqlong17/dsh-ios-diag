## 背景

包名还叫「mem」，但能力已经覆盖：装真机前体检、内存、日志、调用栈、pcap 解析、
统一事件表、报告、代码健康扫描。名字会误导使用者（尤其是别的模型），以为只测内存。

## 目标与非目标

**目标**

- 包名 / 插件 id / RPC 路由 / 面板 module id / MCP server 名 → `dsh-ios-diag`。
- GitHub 仓库改名（旧地址 301 跳转），本地 remote 同步。
- 版本 0.4.0，打 tag。
- **工具名不动**：`ios_mem_*` 只覆盖内存 8 个，其余已是 `ios_log_*` / `ios_hang_*` /
  `ios_preflight` / `ios_net_analyze` / `ios_events_*`，改前缀会让用户已有命令失效。

**非目标**

- 不改写历史测量报告与 `git-checkpoints.jsonl`（它们是时间点记录）。
- 不改面板 tab 标题（面板内容仍以内存为主，标题「内存」是准确的）。
- 不改工具行为。

## 方案

1. 目录改名 → 替换包内 18 个文件里的名字（跳过历史记录目录）。
2. 重建 `client.js`（module id / PANEL_ID / ROUTE / NS 全变）。
3. profile 里 `remove_bundle` 旧的、`install_bundle` 新的。
4. GitHub `gh repo rename` + `git remote set-url`。
5. 版本 0.4.0，tag 推送。

## 被否决的方案

| 方案 | 否决理由 |
| --- | --- |
| 只改 README 不改包名 | 安装路径、RPC 路由、面板 id 仍是 mem，误导依旧 |
| 连工具名一起改成 `ios_diag_*` | 破坏已有调用与文档；工具前缀按能力分本来就更清楚 |
| 保留旧目录做软链 | 两套路径长期并存，重装时容易装错 |
