## 背景 / 问题

导出、报告、查询现在只能通过对话里的工具调用；面板只能看实时曲线。
用户在面板上想「把这一段存下来 / 生成报告 / 找回上次那次」时，没有入口。

## 目标与非目标

**目标**

- 面板加「导出」按钮：把当前采样导出成 run（复用 `ios_events_export`）。
- 面板加「记录」区：列出历史 run（时间、事件数、链接数、有没有报告），最多 20 条。
- 每条记录可「生成报告」：落到 `docs/measurements/<项目>/`，并在面板显示路径。
- RPC 新增 `runs` / `report` 两个操作；报告逻辑从脚本挪进 core，CLI 与面板共用。
- 样式收敛：按钮、列表行、空状态统一。

**非目标**

- 不做删除/重命名 run。
- 不在面板里读报告全文（路径够用，正文太长）。
- 不做跨项目聚合。

## 方案

1. `core/report-run.js`：`generateReport({dir, project, title, slug})` —— 读 jsonl、渲染、写文件、返回路径。
   `scripts/report-from-run.mjs` 改为调用它（避免两份实现）。
2. `core/runs.js`：`listRuns(limit)` —— 扫 `_runs/`，读每个 run 的事件/链接数与首末时间，标 `hasReport`。
3. `index.js` 的 RPC dispatch 增加 `runs` / `report`。
4. `client/40-panel.js`：导出按钮、记录区（列表 + 每行「报告」）、路径展示；样式统一。

## 被否决的方案

| 方案 | 否决理由 |
| --- | --- |
| 面板直接渲染报告全文 | 侧栏太窄；路径 + 交接消息更实用 |
| 记录存数据库 | 目录就是记录，读文件更简单 |
