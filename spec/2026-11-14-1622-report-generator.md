## 背景 / 问题

`ios_events_export` 只产出 `events.jsonl` + `links.jsonl`，报告仍然要人手写；
报告和交接消息的格式靠记忆维持，迟早会不一致。

## 目标与非目标

**目标**

- `core/report.js`：`summarizeRun` / `deriveFindings` / `renderReport` 三个纯函数。
- `scripts/report-from-run.mjs`：把一份 run 落成 `docs/measurements/<项目>/<时间>-<主题>.md`。
- 与 `scripts/handoff.mjs` 串起来：生成报告 → 出可粘贴消息，中间不需要人改格式。

**非目标**

- 不做自动根因分析；`deriveFindings` 只标明显异常（增长 ≥10%、峰谷差 ≥50MB、有错误日志）。
- 不替被测项目写建议里的具体文件——那些要人补。

## 参考实现

- 报告结构沿用 `docs/measurements/README.md` 的六段模板（与 handoff 的解析字段对齐）。
- 不采用「LLM 生成报告」：同一份数据每次措辞不同，无法比较；规则生成才可回归。

## 方案

- 统计（纯函数）：计数、内存起止/峰谷/变化、打点、日志错误、链接事实/推断。
- 疑点（规则）：增长 ≥10%、峰谷差 ≥50MB、错误日志、推断链接提示。
- 渲染：固定六段，数据表 + 疑点 + 建议 + 复现。
- CLI：`--run` / `--project` / `--title` / `--slug`，输出绝对路径。

## 被否决的方案

| 方案 | 否定理由 |
| --- | --- |
| 直接让模型写报告 | 措辞不可回归，数字容易被润色掉 |
| 报告里内嵌原始数据 | 与本仓库「_runs 不入库」的约定冲突；报告只放路径 |
