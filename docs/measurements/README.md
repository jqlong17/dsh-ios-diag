# 实测记录

工具只读被测项目，**所有测量结果都写在这里**，不写进被测仓库。

## 目录约定

```
docs/measurements/
  <项目 slug>/                 # 例如 dsh-pocket-ios
    <YYYY-MM-DD-HHMM>-<主题>.md
```

按项目分一级目录、按时间分文件：同一个项目能按时间线排，不同项目互不污染。
项目 slug 用被测仓库名，不要用设备名（同一项目会跑多台设备）。

## 一份记录至少要有

| 段 | 为什么 |
| --- | --- |
| 头部元信息 | 项目 / 时间 / 设备 / 构建 / 采集参数，缺一个数就没法复现 |
| 摘要 | 三行以内，给没看过原始数据的人 |
| 数据表 | 原始读数，不要只留结论 |
| 异常与疑点 | 排序反常、增量对不上、口径差异 |
| 给被测项目的排查建议 | 具体到文件/行为，不要写「优化一下」 |
| 复现方式 | 命令原样可粘贴 |

## 交接给被测项目

跑完填好记录，用脚本生成一段可粘贴的消息（含绝对路径）：

```bash
node scripts/handoff.mjs --report docs/measurements/dsh-pocket-ios/2026-11-14-1425-stress-footprint.md
```

把输出粘到那个项目的会话里，它按绝对路径读报告、自己排查。
